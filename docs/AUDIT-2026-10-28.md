# MCAT app audit — October 28, 2026

## Scope and outcome

Reviewed the browser application, subject progression, timers, local persistence, HTML rendering, service worker, question-bank validator, and local development server. The baseline was commit 4fe4b5eefb1a76f8f7762ae59b5383660cef722a. This is a source and regression review, not an independent penetration test or certification of every scientific explanation.

Three local regression suites pass. Content validation reports **0 structural errors and 35 editorial warnings**. A Chrome smoke test and cross-platform regression workflow are included; their execution status is recorded in the pull request's checks. A local interactive browser attempt was blocked by the computer-use environment and was not counted as a successful test.

## Verified findings and fixes

| Area | Finding | Fix and practical effect |
|---|---|---|
| HTML rendering | The formatting helper passed raw HTML through to HTML sinks. Existing notes were escaped, but stored answer text and future authored content could reach this helper. No remote input endpoint or demonstrated remote exploit was found. | Escape text before adding the app's bold/cloze markup; add a resource policy and referrer policy. HTML-like text stays text. |
| Local storage | Parse/write failures were silently ignored; malformed preference types could crash initialization. | Show read/save/delete warnings, check top-level data shapes, and normalize preferences. Nested records are not fully schema-validated. |
| Exam resume | A synchronously expired section could transition to break/results and then continue rendering its old question. Repeated end actions could record evidence twice. | Stop rendering when the timer transitions phase, mark completed exams, and guard already-ended sections. |
| Final review | The review window was recalculated from days remaining, so it shrank away before the test. Millisecond-based date offsets could drift at daylight-saving boundaries. | Anchor the review window to the original planning horizon and use calendar-day arithmetic. |
| Recall speed | Time spent choosing a runner-up could inflate measured fluency. | Use the original answer-selection time, excluding reflection time and the recall-first reveal delay. |
| Memory estimates | Immediate repeats could multiply long-term stability as if retrieval occurred after a delay. | Cap correct within-day stability gains at 10% per repeat. Delayed review remains necessary; this cap is a heuristic. |
| Mini-test reinforcement | Review omitted the actual passage text/figures and subsequent practice did not specifically lead with missed discretes. | Include source passages/figures in review; prioritize actual missed discretes before filling the session with same-subject practice. |
| Progress reset | Fluency history was omitted from reset. | Include fluency in the reset keys. |
| Offline support | Activation deleted unrelated caches; cache-write rejections could go unhandled; the worker intercepted unrelated same-origin requests. | Limit interception to listed assets, preserve unrelated caches, catch cache-write failure, and clear fallback timers. |
| Development server | A path-prefix check lacked a directory boundary and private dot paths were served. | Resolve the root, require a separator-bounded child path, deny dot paths, and handle unsupported methods/bad requests. This helper is loopback-only; it is not the GitHub Pages production server. |

## Validation

- Application, progression, and service-worker scripts parse.
- Existing final-two and real-question-bank progression suites pass.
- Audit regressions exercise HTML escaping, storage failures, review-phase persistence, daylight-saving civil dates, fluency timing, conservative same-day repetition, expired first/final exam sections, duplicate guards, mini review, targeted reinforcement, reset behavior, and cache isolation/quota failures.
- The content validator loads all data scripts, including authored variants and both exams. It checks structure and common cues; it does not independently establish scientific correctness.
- GitHub Actions runs Node checks on Windows and Linux, parses the PowerShell helper, and runs a real headless Chrome smoke test on Linux. Actions are pinned to commit SHAs and checkout credentials are not persisted.

## Learning-design assessment

Retrieval practice and practice distributed over time are reasonable foundations; a [systematic review of health-professions education](https://pmc.ncbi.nlm.nih.gov/articles/PMC11078833/) found benefits in many included experiments, with heterogeneous methods and outcomes. This supports the general approach, not the app's exact implementation or a guaranteed MCAT gain.

The [AAMC describes the MCAT](https://students-residents.aamc.org/about-mcat-exam/about-mcat-exam) as assessing problem solving, critical thinking, and prerequisite science knowledge. It is not a clinical competency assessment. Same-subject passages, data interpretation, CARS, unfamiliar wording, and fresh full-lengths matter alongside fact recall.

The 20-fact/70% readiness thresholds, two-passage criterion, seven-day mini cooldown, speed targets, memory estimates, and score conversions remain transparent product heuristics, not validated cutoffs. Final-two tracking measures whether the correct answer was shortlisted; it does not establish scientific closeness or deserve extra score credit. Immediate success should not be labeled long-term mastery without delayed evidence. Confidence calibration and optional self-explanations are useful prompts, but a learner's confident explanation can still be wrong.

## Remaining limitations

- Inline event handlers still require an inline-script allowance in the content security policy. A future event-listener refactor can remove that allowance. No claim of an XSS-proof application is made.
- Local storage is device/browser-specific, can be lost, and is not an encrypted backup. Visible failure warnings do not recover lost data. Nested corrupted records may need additional validation.
- Full scientific and editorial peer review remains separate from this code audit. Familiarity with reused passages can inflate results even though full-length items are held out from subject progression.
- The memory model and score estimates are not calibrated against a prospective MCAT cohort, and no learning tool can guarantee maximum potential or a test score.
